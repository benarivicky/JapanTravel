## תקציר מנהלים

- האפליקציה: Next.js 15.5.20 + Firebase (Auth, Firestore, Storage), עם נתיבי שרת (link-preview, image-proxy) ומפתחות צד־שרת (Google AI, Google Maps).
- התשתית לפריסה ל‑**Firebase App Hosting** כבר קיימת בריפו (apphosting.yaml, cloudbuild.yaml, DEPLOY.md, GitHub Actions) — זו האופציה המומלצת: עלות ~0–5 $ לחודש וקושי נמוך.
- **תנאי סף לכל אופציה:** רוטציית כל הסודות שדלפו באירוע האבטחה מ‑07.07.2026 (הקונטיינר נפרץ וכל משתני הסביבה הודלפו). אסור לפרוס עם המפתחות הישנים.

## אפשרויות פריסה — עלות ורמת קושי

> העלויות הן הערכות נכון ליולי 2026, לאפליקציה בתעבורה נמוכה (אתר טיול משפחתי). כדאי לאמת מול דפי התמחור לפני החלטה סופית.

### אופציה 1 — Firebase App Hosting ⭐ (מומלץ)

| | |
|---|---|
| **עלות חודשית** | **~0–5 $** (עם `minInstances: 0` כפי שמוגדר היום). דורש תוכנית Blaze (תשלום לפי שימוש): Cloud Run בתוך שכבת החינם ברוב החודשים, Cloud Build ~0.003 $ לדקת build מעבר לחינם, אחסון images ~0.10 $ ל‑GB, תעבורה 10GB חינם ואז ~0.15 $ ל‑GB. אם יוגדר `minInstances: 1` (ללא cold start) — קפיצה ל~15–25 $ לחודש |
| **רמת קושי** | **קלה (1/5)** — ~1–3 שעות. הכול כבר כתוב: apphosting.yaml, DEPLOY.md, סקריפטים |

| **חסרונות** | Cold start כשאין תעבורה; תלות ב‑Google; דורש כרטיס אשראי (Blaze) |

**מסלול מומלץ בתוך האופציה:** Track C (אינטגרציית GitHub מובנית) — מחברים את הריפו בקונסולת Firebase, מגדירים ענף live, מזינים סודות, וכל push פורס אוטומטית. Track A (GitHub Actions) נותן שליטה מלאה ב‑CI אם רוצים בדיקות לפני פריסה.

## המלצה

**אופציה 1 — Firebase App Hosting, מסלול Track C** (אינטגרציית GitHub מובנית), ואם רוצים בדיקות CI לפני כל פריסה — Track A (GitHub Actions).

נימוקים:
- כל התשתית כבר כתובה ובדוקה בריפו — הזמן להשקה הוא הקצר ביותר.
- העלות בפועל צפויה להיות קרובה ל‑0 $ בתעבורה של אתר טיול משפחתי.
- מעביר את נטל האבטחה של השרת לגוגל — הלקח המרכזי מאירוע ה‑cryptominer.
- Firestore/Auth/Storage כבר באותו פרויקט GCP — בלי CORS ובלי חיבורים חוצי־ספקים.

## שלבי ביצוע (לאופציה המומלצת)

1. **שלב 0** — רוטציית סודות + התראת תקציב (ראו למעלה). ⚠️ חוסם.
2. **יישור ענפים** — להחליט מהו ענף ה‑live (מומלץ `master`) ולעדכן את DEPLOY.md ואת הערת ה‑compose בהתאם.
3. **חיבור Backend** — קונסולת Firebase → App Hosting → Add backend → חיבור הריפו → הגדרת ענף live.
4. **הזנת סודות** — כל המשתנים מ‑.env.example (בערכים החדשים!) כ‑Secrets ב‑App Hosting.
5. **פריסה ראשונה** — push לענף ה‑live; מעקב אחר ה‑rollout בקונסולה.
6. **בדיקות עשן** — התחברות, צפייה במסלול, תצוגת תמונות (image-proxy), link-preview, מסכי אדמין.
7. **דומיין** — חיבור `japantravel.amitkuzi.com` כ‑custom domain (רשומת CNAME; TLS אוטומטי).
8. **ניטור** — Cloud Logging (כלול), התראת תקציב, בדיקת `npm audit` שנותרו פתוחים מהאירוע.

## נסיגה (Rollback)

- App Hosting שומר rollouts קודמים — חזרה לגרסה קודמת מהקונסולה בלחיצה.
- בתקלה חמורה: ניתוק הדומיין או הקפאת ה‑backend; הקוד ממשיך לרוץ מקומית ב‑docker compose לצורך debug.
